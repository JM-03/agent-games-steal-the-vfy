# Treasury spend proof — spend 5 VFY within the committed cap

A real Groth16 proof from the official `vfy-policy` circuit, generated by
`npm run demo:treasury` (example 2): spend 5 VFY, treasury policy
`[5,50,20,0,0,0,0,0]` (spend cap 5), commitment `0x1b633a5a1e59fadd82344fc383f6aef95d6b043d46f4fe87235bfc99d88a2a24`.

## Verify (no repo code runs — only snarkjs)

```bash
npm run verify:treasury
```

The verification key is the same official key as the turn-1 proof:
`evidence/proof-turn-1/verification_key.json` (exported from
`circuits/vfy-policy_final.zkey`).

## What this proves — and what it does not

- It proves the spend of 5 is inside the committed cap. The circuit
  knows balances and caps — it does NOT know addresses. The allowlist
  check (recipient is on the list) is a guard-layer check, not a
  circuit check, and is labelled as such on the demo page.
- It does NOT prove on-chain finalization — that needs a Kurier job id
  (the first Steal Finalized job id is 2d523ed8-e255-11f1-838e-1e6a0d14f999, 17 Nov 2026 — see the README's "Verified on mainnet" section).
