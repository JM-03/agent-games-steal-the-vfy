Steal the VFY — every move provably bound to a pre-committed strategy

Commit once, prove every move.

An agent that can only do what it committed to before acting — proven in zero knowledge. Before a match, the owner picks 8 strategy numbers and a random salt and publishes only a Poseidon commitment; the strategy stays secret. Each turn, the agent decides strictly by the official circuit's decision list, generates a Groth16 proof against the official vfy-policy circuit that the move is permitted by the committed strategy, self-verifies it locally, and only then answers. A wrong move cannot be proven at all — the circuit refuses, and the agent fails closed to HOLD. Local self-verification is only the first gate: the proof that counts is the one verified on zkVerify mainnet, by a verifier the agent does not control (see "On-chain evidence" below).

How to read this page

This page is a transcript of real local runs of the repo's demo scripts, recorded 15–16 Nov 2026 (main + defensive matches on 15 Nov; refusal, treasury and reveal transcripts on 16 Nov). What is real: the turn handler (src/turn.ts), the Groth16 proofs (snarkjs + official vfy-policy circuit), and the local self-verification of every proof. What is simulated: the opponent (a fixed script) and the balance resolver (documented rules in the repo — FORTIFY costs 2 VFY and blocks up to 6 on the next turn; EXTRACT steals up to the requested amount; both sides' gains are computed from start-of-turn balances and applied together). The treasury examples are precomputed transcripts of npm run demo:treasury — the verdicts are what the script printed, labelled as such. The match is a local simulation, not a tournament game — the Steal tournament entries are locked, so this demo + proofs are the entry.

Proof timings vary run to run; the moves, balances and final scores are deterministic. Reproduce it yourself: npm install && npm run build && npm run demo (see the repo README).

The loop, end to end

  1. Commit — owner publishes a Poseidon commitment over the strategy + salt. The strategy itself is never published.
  2. Move — each turn, the agent decides strictly by the circuit's decision list: FORTIFY → HOLD → EXTRACT.
  3. Prove — a Groth16 proof is generated against the official vfy-policy circuit and self-verified locally. A move outside the policy has no proof at all.
  4. Kurier — proofs are submitted to Kurier for verification on zkVerify mainnet (see status below).
  5. Result — only a proven move is answered; anything else fails closed to HOLD.

Verification is the gate, not a badge: without the proof, the move does not happen. A refused move produces no proof, so no Kurier receipt exists for a refusal — the demo output above is the evidence.

Reveal — commit → act → reveal

After the match, the owner opens the DEMO strategy. The defensive commitment 0x1b63…a2a24 was published before the defensive matches; its params and salt are revealed here, so anyone can recompute the commitment and confirm the strategy was fixed in advance:

npm run reveal:demo

Reveal — demo strategy (defensive commitment ONLY)
params:     [5,50,20,0,0,0,0,0]
salt:       0x1569514d09c0dddef31b99d04671016330ef290b81f69808be10b873cca5fc
commitment: 0x1b633a5a1e59fadd82344fc383f6aef95d6b043d46f4fe87235bfc99d88a2a24

Recomputing commitment = Poseidon(params, salt) ...
recomputed: 0x1b633a5a1e59fadd82344fc383f6aef95d6b043d46f4fe87235bfc99d88a2a24
MATCH — the revealed strategy is exactly the one committed to before the match.

Only the DEMO commitment is ever revealed. The main commitment (0x0b9f…1cb39) and its salt stay secret — there is no ceremony in which the main salt is revealed. A commitment nobody can ever check is a claim; a commitment that is revealed and recomputed is evidence.
