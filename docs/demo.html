Steal the VFY — every move provably bound to a pre-committed strategy

Commit once, prove every move.

An agent that can only do what it committed to before acting — proven in zero knowledge. Before a match, the owner picks 8 strategy numbers and a random salt and publishes only a Poseidon commitment; the strategy stays secret. Each turn, the agent decides strictly by the official circuit's decision list, generates a Groth16 proof against the official vfy-policy circuit that the move is permitted by the committed strategy, self-verifies it locally, and only then answers. A wrong move cannot be proven at all — the circuit refuses, and the agent fails closed to HOLD. Local self-verification is only the first gate: the proof that counts is the one verified on zkVerify mainnet, by a verifier the agent does not control (see "On-chain evidence" below).

How to read this page

This page is a transcript of real local runs of the repo's demo scripts, recorded 15 Nov 2026. What is real: the turn handler (src/turn.ts), the Groth16 proofs (snarkjs + official vfy-policy circuit), and the local self-verification of every proof. What is simulated: the opponent (a fixed script) and the balance resolver (documented rules in the repo — FORTIFY costs 2 VFY and blocks up to 6 on the next turn; EXTRACT steals up to the requested amount; both sides' gains are computed from start-of-turn balances and applied together). The match is a local simulation, not a tournament game — the Steal tournament entries are locked, so this demo + proofs are the entry.

Proof timings vary run to run; the moves, balances and final scores are deterministic. Reproduce it yourself: npm install && npm run build && npm run demo (see the repo README).

The loop, end to end

  1. Commit — owner publishes a Poseidon commitment over the strategy + salt. The strategy itself is never published.
  2. Move — each turn, the agent decides strictly by the circuit's decision list: FORTIFY → HOLD → EXTRACT.
  3. Prove — a Groth16 proof is generated against the official vfy-policy circuit and self-verified locally. A move outside the policy has no proof at all.
  4. Kurier — proofs are submitted to Kurier for verification on zkVerify mainnet (see status below).
  5. Result — only a proven move is answered; anything else fails closed to HOLD.
